# LightX Project Starter Guide

Welcome to your new LightX project! This starter guide will help you understand the end-to-end "Bare-Metal" flow.

## 1. Setup the Database
An exhaustive example schema has been provided in `migrations/example/init_mysql.sql`.
1. Make sure you have a MySQL server running locallly or remotely.
2. Create a database named `example` (e.g., `CREATE DATABASE example;`).
3. Import the SQL file: `mysql -u root -p example < migrations/example/init_mysql.sql`.
4. Open the `.env` file in your project root and update the `EXAMPLE_DATABASE_URL` connection string if your credentials differ.

## 2. Generate the DAOs (Data Access Objects)
LightX is a "Database-First" ORM. You do not define models manually; Daox generates them for you with absolute performance.
Run the compilation command:
```bash
npx daox generate
```
This will read your `.env` and extract schemas into high-performance TypeScript DAOs available at `contexts.daox.example`.

## 3. End-to-End Workflow Examples
HTTP requests are handled by two layers:
1. **Handlers** (`src/handlers/`): Define routing, methods, and configurations.
2. **Business Objects (BO)** (`src/bo/`): Contain your pure business logic.

Here are three exhaustive examples:

### A. Read operation without parameters
**Goal:** Retrieve the list of active users. (Requires the `active_users` view).

**1. Handler (`src/handlers/example/users/list.ts`)**
```typescript
export const route = { method: "GET" };
```

**2. Business Object (`src/bo/example/users.ts`)**
```typescript
export async function list(payload: any, contexts: any) {
  // Queries all elements from the active_users view without constraints
  // Note: listByOffset handles massive datasets efficiently
  const users = await contexts.daox.example.ActiveUsersDao.listByOffset(100, 0);
  return { status: 200, users };
}
```

### B. Read operation with mandatory and optional parameters
**Goal:** Retrieve a user by email (mandatory) and optionally filter by their role.

**1. Handler (`src/handlers/example/users/getByDomain.ts`)**
```typescript
export const route = { method: "GET" };
```

**2. Business Object (`src/bo/example/users.ts`)**
```typescript
export async function getByDomain(payload: any, contexts: any) {
  if (!payload.email) {
    return { status: 400, message: "Email parameter is mandatory" };
  }
  
  // Mandatory search via unique index generated by Daox
  const user = await contexts.daox.example.UsersDao.getByEmail(payload.email);
  
  if (user && payload.with_role) {
    // Optional query to query the relation
    const roles = await contexts.daox.example.UserRolesDao.listByUser_id(user.id);
    user.roles = roles;
  }
  
  return { status: 200, user };
}
```

### C. Write operation (Create)
**Goal:** Create a new user securely.

**1. Handler (`src/handlers/example/users/create.ts`)**
```typescript
export const route = { method: "POST" };
```

**2. Business Object (`src/bo/example/users.ts`)**
```typescript
export async function create(payload: any, contexts: any) {
  // Explicit properties mapping guarantees security against Mass Assignment
  const newUser = {
    email: payload.email,
    first_name: payload.first_name,
    last_name: payload.last_name,
    status: 'active'
  };

  // The DAO enforces strict type validation before inserting
  const userId = await contexts.daox.example.UsersDao.insert(newUser);
  
  return { status: 201, message: "User safely created", id: userId };
}
```
